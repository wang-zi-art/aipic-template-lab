# 系统模板测试模块：核心设计与规范

> 用途：供后续 Skill 和人工执行任务时优先阅读。本文只保存稳定规则；具体数据以素材档案、后台回读和执行报告为准。
> 状态：正式素材与九个项目 Skill 已迁入；当前没有新项目候选登记或执行记录。新项目活动 MCP 入口留待切片五切换。

## 1. 目标与数据边界

通过固定编号找到模板类型与测试输入，对同一测试用例做可追溯的横向比较。新项目 `mcp-test/materials/` 是正式素材目录；新 MCP 的 `inputRoot` 已指向该目录，活动入口仍在原项目。新执行计划、结果与报告将保存在新项目忽略的 `.local/` 中。后台数据库保存真实模板、版本、任务和积分状态，本地文档不能代替后台状态。原项目素材仍保留为本轮回退来源，不再作为新项目的日常维护位置。

## 2. 最小目录与各文件职责

```text
mcp-test/
├─ CORE.md                          核心规则与 Skill 入口
├─ README.md                        目录导航与当前进度
├─ docs/                            详细设计
├─ materials/
│  ├─ catalog.json                  TPL 编号 → 名称、目录
│  └─ TPLxxxx-*/
│     ├─ manifest.json              素材、栏位、图片组、测试用例
│     ├─ candidates.json            后续新建的候选关联；目前不存在
│     ├─ competitor/                 最多一组友商参考，可缺失
│     └─ test-inputs/Sxxx/          测试上传图，按栏位顺序
└─ archive/                          一次性迁移资料
```

`TPLxxxx` 是模板类型编号，不是后台模板 ID；`Sxxx` 是一组有序上传图；`Txxx` 是“图片组 + 确切补充描述”的测试用例，也是 MCP 的 `sampleId`。编号在各自作用域内保持稳定，已参与测试的图片、顺序或描述变化时新建编号，不覆盖旧定义。

## 3. 必须遵守的素材规则

- 友商上传图和效果图只作参考；即使缺失部分图片也如实记录，不能自动当作测试输入。
- `manifest.json` 是该模板素材定义的唯一维护位置。图片文件名标明 `input_01`、`input_02` 等顺序，提交时仍须按档案中的有序数组及后台当前版本的真实 `slotKey` 核对。
- 同一 `S` 可对应多个 `T`，用于比较不同补充描述；描述原文或 `null` 必须明确记录。泛化留存测试须使用未参与调词的图片组。
- 素材相对路径不得跳出正式根目录。新增或修改素材时更新对应档案和目录索引；不依赖每次全量扫描重建上下文。

## 4. 候选与执行规则

- 未来新建的 `candidates.json` 负责将一个 `TPL` 的 A/B/C 等候选关联到准确的后台 `templateId`、`versionId`，记录本地研发状态和停用原因。新项目目前没有候选关联；仅凭名称、`TPL` 编号或旧项目 UUID 不得自动提交付费试用。
- 执行前先确定候选和 `T` 用例，再回读后台确认身份、版本、状态、最新 revision、模型参数与图片栏；核对文件存在、图片顺序及补充描述。任何关键条件缺失或不符，先报告缺口，停止相关付费提交。
- 同一轮横向比较中，每个候选对同一 `T` 使用相同图片、顺序、补充描述和生成参数。提交和结果以 MCP 执行报告为准；本地停用记录不等于后台已停用或删除。
- 批量试用先核对整批候选和素材，再一次调用 MCP 批量工具，由工具内部逐项串行提交；文件夹汇总只整理本轮原图与结果，不重新生图，也不代替后台任务状态。

## 5. Skill 阅读顺序与当前能力

先读本文，再按任务读取 `materials/catalog.json`、目标模板的 `manifest.json`；涉及候选时读取新项目目标 `candidates.json`（若存在），并回读后台。规则细节见 `docs/material-structure-design.md` 与 `docs/candidate-registry-design.md`。九个 Skill 的中文入口见 `docs/skills/README.md`；只读核验命令为 `corepack pnpm materials:verify`。目前有 19 个模板类型和 71 张图片；`TPL0001` 有两个测试用例，`TPL0002` 有三个无补充描述的开发用例，`TPL0003` 尚无正式 `T` 用例，`TPL0019` 有四个无补充描述的开发用例。新项目中所有已有 `slotKey` 均须在候选试用前回读后台核对。
