# 结果对比静态样稿

从文件管理器打开 [`index.html`](index.html)，再进入三套独立方案。无需启动服务、安装前端依赖或配置管理员会话。

| 页面                               | 核心方式               | 主要交互                                   |
| ---------------------------------- | ---------------------- | ------------------------------------------ |
| [`workbench.html`](workbench.html) | 一次只看一个用例       | A/B/C 同屏，同步缩放和平移；方向键切换用例 |
| [`matrix.html`](matrix.html)       | 先看整批用例矩阵       | 状态筛选、搜索、点击用例展开三图           |
| [`detail.html`](detail.html)       | 专注同一位置的局部差异 | 拖动归一化选区，同时更新三个局部放大窗     |

逐例评审台另外提供三套**相同功能、不同视觉样式**的页面：[暖白与墨绿](workbench.html)、[冷白与蓝灰](workbench-slate.html)、[石墨与蓝紫](workbench-midnight.html)。每页上方的“视觉方案”可直接切换并保留当前测试用例，三页共用 `workbench.js`、演示数据和响应式布局；旧深青配色已停用。批次联系表和局部差异台不受本轮样式调整影响。

## 数据与边界

三套样稿只共享 `demo-data.js` 中模拟 `comparison/summary.json` 主要字段的用例和状态。样稿复用 `mcp-test/materials/TPL0019-eyelid/` 的正式测试输入图，并以显示滤镜模拟候选差异；这些图片**不是** A/B/C 生图结果，不代表任何候选质量、后台身份或真实任务状态。样稿不读取 `.local/`、不调用 API、不提交任务，也不修改正式素材。

选定的石墨蓝紫方案现已接入真实批次汇总：`apps/mcp/src/batch-comparison.ts` 每次生成或更新汇总时，都会将 `review.html`、`review.css`、`review.js` 和选定样式写入对应的 `comparison/`，并把本轮 `summary.json` 数据安全内嵌到 `index.html`。直接打开 `.local/codex-template-mcp/outputs/<executionId>/comparison/index.html` 即可使用，无需本地服务。页面显示真实结果，不使用演示滤镜；从 `report.json` 派生的汇总是查看快照，状态仍以原报告和后台回读为准。当前项目尚无新执行，因此仓库中没有真实结果页实例。

图片路径按本仓库目录布局解析。若图片不显示，先核对当前工作目录包含完整 Git LFS 图片，而非指针文本；页面会对不可读取的结果显示占位。关闭 JavaScript 后交互不可用。局部差异台使用现代浏览器的 Canvas 2D 能力；选区按图片宽高比例定位，构图差异较大时应结合全图判断。

## 本轮验收

- 从 `index.html` 进入任意方案，三套页面均能独立打开并显示显著的“演示数据”提示。
- 逐例评审台可切换四个用例、查看原图、同步缩放和平移成功结果；无图状态清晰可见。
- 在逐例评审台的三种视觉样式之间切换，当前样式高亮，且同一套交互在每页均可用。
- 批次联系表可按状态筛选并搜索用例，展开后能同时看到 A/B/C 状态和可用图片。
- 局部差异台可在任意可用全图上拖动选区，三个放大窗随之更新；尺寸滑块和重置按钮有效。
- 在桌面、平板和窄屏尺寸检查布局、可读性、图片加载和键盘焦点。
