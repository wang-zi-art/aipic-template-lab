# 系统模板候选提示词

本技能承接已确认的验收标准，处理 `system-template-prompts` 的第三步。输出可独立复制和比较的候选文本，不把某个模板的示例措辞当作通用规则。

## 读取与判断

1. 读取当前会话或指定研发记录中**已确认的完整验收标准及版本**。若只有初稿或版本不明，先说明缺口；不自行更改硬性标准或把未确认推断写进提示词。
2. 先读项目 `mcp-test/CORE.md`，再通过 `mcp-test/materials/catalog.json` 定位指定模板的 `manifest.json`。读取 `sourceNote`、`slots`、`competitorReference`；按登记路径和顺序查看可用的友商上传图、效果图。区分原始说明、图片可见事实与推断；图片缺失或仅为截图时说明证据范围，不补造细节。友商效果图只作目标参考，不是正式生成时自动输入的图片。
3. 结合当前会话中已确定的模型、生成参数和可用测试用例。新建测试候选未另行指定时，模型默认 `gpt-image-2.5`，分类默认“测试”，允许补充描述但不填写推荐内容，效果图、栏位示例图和预设图默认留空；用户对该模板明确指定的设置优先。模型或分类 ID 留待创建前从 `get_admin_context` 解析和核对，不硬编码历史 ID。提示词不写死与用户可选参数冲突的尺寸。已有 `T` 用例可用于测试建议；没有 30 组素材也可完成候选设计，不虚构样本。

## 创建配置交接

在候选正文前给出一份供负责人审核的创建配置：本轮拟创建的候选名单、模型、分类、补充描述开关与可选推荐内容、展示素材，以及按图片顺序排列的栏位 `key`、名称、`required: true` 和完整上传要求。当前 MCP 只接受 1 至 4 个必填栏位；若确认的业务需求需要可选栏位，说明能力缺口，不伪装成必填。候选名称默认为“<素材档案名称>（测试）A／B／C”，每个候选另给一段准确简介；若这些字段已有确认版本，沿用确认版本。栏位配置可在候选间共用，但每个候选的模型作用和基础提示词必须完整独立。

`slots.order` 决定图片来源顺序。素材档案中的 `slotKey: null` 表示友商参考尚未映射到后台栏位，不妨碍为**新建**候选拟定稳定、互不重复的栏位 `key`；将拟定值明确展示供审核。已有后台候选的栏位以准确版本回读为准，不从档案重造。上传要求是用户可见说明，不进入模型提示词。未指定正式展示素材时写明 `assets: []`，不得把友商参考或试用输入作为展示素材。

候选交付时确认这些字段与 AC、图片顺序和提示词一致。影响实际表单且无法从当前资料确定的内容集中列为待确认项；不要把它留到后台创建时临时拟写。

## 设计候选

生成 2 至 3 条**实现路径确实不同**的候选，仍共同满足同一版验收标准。例如可分别强调主体保留、参考信息分解、局部最小改动；这些只是适用时的设计选项，不能直接套到换装、背景替换等不同功能。每条说明预期优势与待验证风险，不把推测写成实测结果。候选使用 `A-v1`、`B-v1`、`C-v1`；修订某条时递增该条版本，保留所依据的 `AC-vN`。

每条候选按以下结构**完整独立交付**，不得以“同 A”省略内容：

```text
## A-v1：<区分策略的名称>
依据验收标准：AC-vN
模板名称：...
模板简介：...
核心思路：...
预期优势：...
待验证风险：...

### 图片栏1模型作用（<栏位名称>）
<可直接填写后台“模型作用”的完整文本>

### 图片栏2模型作用（<栏位名称>）
<按实际栏位数量继续>

### 完整基础提示词
<可直接填写后台隐藏提示词的完整文本>
```

栏位作用必须按 `slots.order` 和实际图片数量分别写清：该图提供什么、需要保留或迁移什么、哪些内容不能带入结果；多图冲突时明确优先来源。基础提示词要覆盖任务、来源优先级、关键画面关系、质量要求和输出要求；默认开启的可选用户补充描述不能推翻已确认的身份、图片来源等硬性标准。每段可复制文本使用普通文本或 `text` 代码块，不使用 `diff` 等会混入加减号的格式。

## 首轮测试建议

候选后简列需要覆盖的**差异场景**、可用的 `T` 用例、同轮固定的模型与生成参数，以及重点比较的 AC 编号。不同候选对同一 `T` 应使用相同图片顺序、补充描述和参数；若现有用例不足，直接指出缺口。示例道具或示例补充描述仅在对应模板和用例确有记录时使用，不写成所有测试的固定输入。

本技能只交付候选文本和测试建议。没有实际结果时标记“待测试”；不调用付费生图、不创建或更新后台模板，也不宣布候选已通过验收。
