# 模板测试接口使用基线

> 更新日期：2026-09-28
> 用途：供独立项目 Skill 日常核对原项目管理员接口行为；具体字段以本项目契约快照及后台实时回读为准。

## 输入、提示词与模型

- 系统模板版本有 1 至 4 个按 `order` 排列的图片栏。素材档案中的 `slotKey` 是待核对定义；创建候选或付费试用前，须按准确 `templateId`／`versionId` 回读后台当前版本的栏位 `key`、顺序和 revision。
- `uploadRequirement` 面向上传者说明应提供什么图片；`modelRole` 指示模型怎样使用该栏。两者不能互相替代。最终提示词按栏位顺序组合各栏 `modelRole`、版本隐藏基础提示词、允许时的本次补充描述；上传要求不进入模型提示词。
- 模型绑定在模板版本上。试用比例与分辨率必须命中当前模型 `sizes` 的同一组合；`auto` 比例与分辨率必须成对使用。模型有质量选项时按能力提交质量，没有质量选项时省略。旧模板比例字段不能代替实时模型能力。

## 管理员试用与生命周期

- MCP 使用正式平台管理员会话，通过原项目 HTTP API 操作；每个“候选 × T 用例”分别校验输入、申请上传票据、上传、提交和记录。计划中的输入路径相对 `inputRoot`，同一用例的候选保持图片、顺序、补充描述和生成参数一致。
- 本地 `candidates.json` 只关联研发候选与准确后台 ID，后台状态和 revision 以每次回读为准。创建、编辑和删除结果不明时按原执行编号核对，不以新编号重发；同一执行编号不得重新提交付费批次。下载失败可按原执行编号续收，不重新生图。
- 修改测试版本提示词依次执行退回草稿、保存完整表单、重新进入测试并回读；有活跃试用、revision 冲突或任一步失败时停在实际状态。候选软删除只适用于从未发布且没有活跃试用的系统模板。MCP 不执行测试确认或发布，最终由负责人在原项目后台人工处理。
- 报告区分成功、失败、处理中、待核对和未执行。不得记录管理员会话、临时 COS 凭据、对象 Key、签名地址、完整隐藏提示词、图片栏模型作用或供应商原始错误。
